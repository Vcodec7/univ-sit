# Аудит сайта — 5 сентября 2026

Проверено на staging `https://ty.idivles.ru` (ветка визуала + этот патч). Production `py` не трогали.

## Модули: почему они были у админа

Задумка: скрытая учётка `TECH` (env `TECH_EMAIL` / bootstrap), её нет в списках пользователей админки, вход в `/ops` не светится в меню обычного админа.

Факт до патча: у `ADMIN` была полная копия kill-switch — вкладка «Модули» и `POST /api/admin/modules` писали в тот же `moduleFlagsJson`. Документация расходилась: `docs/ops-modules.md` — только TECH, README — «админ или TECH».

**Сейчас:** тумблеры только у TECH через `/ops` → `/api/ops/flags`. Админский API отдаёт 404. В настройках вкладки нет; по старой ссылке — текст без адреса `/ops`. Админ видит только факт «сколько разделов выключено», без кнопок.

## Защита изменений + уведомление разработчика

Любое сохранение настроек сайта и любое переключение модулей:

1. пишется в журнал админки (`adminAuditLog`);
2. письмо на `DEVELOPER_EMAIL` (и/или `TECH_EMAIL`);
3. Telegram: обычные алерты портала + опционально `DEVELOPER_TELEGRAM_CHAT_ID`.

Это не блокирует правку (админ должен уметь менять название/логотип), а сразу сообщает разработчику, кто и что сменил.

Главная тяжелее каталогов: серверный состав секций + картинки. Каталоги в кэше Next отвечают быстро. Узкое место не «всё тормозит», а первая отрисовка home и внешние таймауты отдельных API при деградации сети.

Рекомендации (не в этом патче): не раздувать HTML главной (галерея/карточки), держать Redis для флагов модулей, не дергать Prisma на каждый ISR без тегов.
