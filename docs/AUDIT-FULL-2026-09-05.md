## 1. Вывод одной фразой

Сайт — рабочий контур молодёжного портала: контент создаётся и правится в админке, заявки и брони проходят очередь с уведомлениями, роли режут доступ. **Не всё одинаково удобно править:** гранты/добро/самоуправление, места, новости, клубы, проекты — полноценные формы создать+изменить. **Вакансии и конкурсы в UI в основном «создать и разобрать заявки», без нормального редактирования карточки.** Удаление во многих разделах без подтверждения. Занятость залов была спрятана (в меню добавлена).

## 2. Админ: создание и правка записей

### 2.1 Работает создать и изменить (удобно)

| Раздел | Путь | Создать | Изменить | Удалить | Замечания |
|--------|------|---------|----------|---------|-----------|
| Проекты | `/admin/projects` | да | да | да, **без confirm** | JSON-поля ролей/дорожной карты легко сломать |
| Клубы | `/admin/clubs` | да | да | да, без confirm | то же |
| Пространства | `/admin/spaces` | да | да | да, без confirm | QR чекина — отдельная страница |
| Куда сходить | `/admin/places` | да | да | да, без confirm | отзывы: одобрить/отклонить |
| Гранты / Добро / Самоуправление | `/admin/programs` | да | да (`?edit=`) | да, **теперь с confirm** | поля: раздел, статус, анонс, HTML, организатор, место, сумма, места, даты, орган (bodyType), ссылка, теги, обложка |
| CMS-страницы | `/admin/pages` + new/edit | да | да | да (не системные) | системные slug нельзя сменить |
| FAQ | `/admin/faq` | да | да | да, **есть confirm** | эталон по аккуратности |
| Новости | `/admin/news` | да | да | да, без confirm | VK-видео только `video_ext.php` |
| Команда «О нас» | `/admin/about-team` | да (upsert) | роль — только передобавить | да | нет отдельной формы «править карточку» |

**Самоуправление / парламент:** в форме админа есть `bodyType`, место, даты, места, описание. Публичные блоки «чем заниматься / кому подходит» подтягиваются по типу органа (PARLIAMENT / COUNCIL / SCHOOL), их **не нужно дублировать в HTML**, но описание в форме всё равно стоит заполнять.

### 2.2 Создать можно, править карточку в UI нельзя или плохо

| Раздел | Что есть | Дыра |
|--------|----------|------|
| Вакансии | Создать работодателя, опубликовать вакансию, разобрать отклики | **Нет формы «открыть вакансию и поправить»** (API `upsertVacancy` с `id` есть). Отказ отклика с жёстким текстом «Не подходит» |
| Конкурсы | Создать, модерировать работы, розыгрыш, победители | **Нет UI редактирования конкурса** (API умеет id) |
| Документы | Загрузить + удалить | Нет заменить файл / поправить метаданные |
| Награды | Выдать бланк | Нет отозвать / править выданный |
| Занятость залов | Поставить служебную бронь | Не было в меню; **снять блок из этой страницы нельзя** |

### 2.3 Только очередь (не «добавление записей»)

Афиша `/admin/bookings` — одобрить/отклонить бронь (отказ с причиной, уведомление).  
Заявки `/admin/applications` — клубы, проекты, гранты, добро, самоуправление.  
Портфолио `/admin/portfolios` — статус + уведомление.

### 2.4 Что поправить в первую очередь (удобство админа)

1. Форма **редактирования вакансии** (подгрузить поля, включая оплату и стек).  
2. Форма **редактирования конкурса**.  
3. `confirm` на удаление проектов, клубов, мест, новостей, пользователей (как у FAQ и теперь у программ).  
4. Причина отказа вакансии — поле, не константа.  
5. Occupancy: кнопка снять служебный слот.

## 3. Роли и что им можно

| Роль | Кабинет | Админка | Сканер | Заявки/брони как участник |
|------|---------|---------|--------|---------------------------|
| Гость | нет | нет | нет | нет (часть каталогов только после входа) |
| USER / PARTICIPANT | да | нет | нет | да, если аккаунт не на модерации и не заблокирован. PARTICIPANT в БД почти косметика |
| MODERATOR | да | только выданные права | если право `scanner` | да |
| ADMIN обычный | да | всё | да | да |
| ADMIN limited | да | только токены в permissions | по правам | да |
| SCANNER | нет кабинета | нет | да | **нельзя** бронировать/откликаться |
| TECH | кабинет да, админка нет | служебный контур отдельно | да | **нельзя** как участник |

Права модератора: `projects`, `clubs`, `spaces`, `places`, `bookings`, `applications`, `pages`, `programs`, `news`, `stats`, `scanner`, `portfolios`, `moderation`, `vacancies`, `contests`.

Только полный ADMIN: пользователи, заявки регистрации, настройки, бэкап, РКН, боты, онлайн, журнал, состояние сервера.

Нового сотрудника после назначения staff-роли режет на смену пароля (`mustChangePassword`).

Модули сайта (`/admin/settings` / модули) могут выключить вакансии, заявки, уведомления и т.д. — тогда API отвечает «раздел выключен».

## 4. Действия участника и подтверждения

| Действие | Подтверждение | Уведомление участнику | Уведомление сотрудникам |
|----------|---------------|------------------------|-------------------------|
| Регистрация | email OTP; если почта лежит — очередь админу | — | да, заявки регистрации |
| Модерация аккаунта | авто через 3 рабочих часа МСК **или** админ | блок участия, пока pending | очередь pending-users |
| 2FA | TOTP второй шаг | — | — |
| Бронь зала / события | автоодобрение или PENDING | да (статус, ICS при одобрении) | да (админка, почта, Telegram/MAX если настроены) |
| Лист ожидания | продвижение когда место | email + in-app | — |
| Заявка клуб/проект/грант/добро/самоупр. | PENDING | «заявка отправлена»; потом одобрение/отказ | боты + админка |
| Отклик на вакансию | автоскрининг | да (отправлен / скрининг не пройден / решение) | очередь вакансий |
| Работа на конкурс | модерация | да | очередь конкурсов |
| Портфолио | модерация | да | очередь портфолио |
| Друзья / сообщения | — | да (если модуль сообщений) | флаги при нарушениях |

Кабинет заявок: `/dashboard/applications`.

## 5. Нарушения, блоки, авторитет

- Переписка: маскирование, флаг, предупреждения, порог автоблока (по умолчанию 5). Тип уведомления `MODERATION` / при бане `SECURITY`.
- Ручной блок на карточке пользователя: причина, история, разлогин.
- Регистрация: антимультиаккаунт по IP/отпечатку, алерты сотрудникам.
- Авторитет: посещения vs неявки (−10 / +4), гейты вакансий и конкурсов. Соцрейтинг отдельно.
- РКН/ПДн: пакет и блоклист ссылок в чате — только полный ADMIN.

## 7. Уведомления (типы)

`MESSAGE`, `FRIEND_REQUEST`, `BOOKING_REQUEST`, `APPLICATION`, `ENTITY_INVITE`, `CHECK_IN`, `PORTFOLIO`, `MODERATION`, `SECURITY`, `ECO`, `CONTEST`, `VACANCY`, `AWARD`, `LEVEL`, `SYSTEM`.

Каналы: колокольчик, web-push (если не тихий час), почта (брони/заявки), Telegram и MAX для очередей броней и заявок (если боты включены). Модуль `notifications` может всё отключить.

---

## 8. Что в этой сессии не кликали живьём

Сканер билетов на телефоне, ESIA/Яндекс/VK вход, SMS-логин, фактическая отправка MAX/Telegram, SMTP, розыгрыш конкурса на проде, бэкап/скачивание, смена роли с `mustChangePassword`, автоодобрение регистрации по крону, конфликт двух броней в одну минуту.

Для приёмки на стенде: завести USER, MODERATOR с одним правом, ADMIN; пройти бронь PENDING, заявку на парламент, отклик на вакансию, флаг в чате, выдачу награды.
