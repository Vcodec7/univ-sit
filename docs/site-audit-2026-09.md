# Аудит портала «Молодёжь Сочи» (YoungPortal)

Дата: 2026-09-06. Версия кода: 1.6.85. Стенд: ty.idivles.ru. Прод py не трогали.

Проверено по коду ACL, флагам модулей, публичным маршрутам, API создания и участия. Живой прогон всех ролей на стенде ограничен тем, что сервисные учётки QA могут быть не заведены; матрица ниже — фактическое поведение кода.

## Роли

| Роль | Публичный сайт | Участие (запись, заявки, конкурсы) | Кабинет | Админка | Сканер | Техпанель |
| --- | --- | --- | --- | --- | --- | --- |
| Гость | Каталоги, новости, FAQ, документы | Нет (нужен вход) | Нет | Нет | Нет | Нет |
| USER | Да | Да, если аккаунт не на модерации | Да | Нет | Нет | Нет |
| PARTICIPANT | Да | Как USER | Да | Нет | Нет | Нет |
| MODERATOR | Да | Да (как участник) + разделы по permissions | Да | Только выданные права | Если есть `scanner` | Нет |
| ADMIN | Да | Да | Да | Полный доступ; limited-admin — только свои права | Если есть `scanner` | Нет |
| SCANNER | Просмотр | **Нет** (`isEndUserRole` / `requireEndUser`) | Ограниченно | Нет | Да | Нет |
| TECH | Обход kill-switch модулей | **Нет** как участник | Не админ | **Нет** (не /admin API) | Да | Да |

`isEndUserRole`: USER, PARTICIPANT, ADMIN, MODERATOR. SCANNER и TECH специально исключены, чтобы служебные учётки не бронировали места и не подавали заявки.

Модерация аккаунта (`moderationPending`) блокирует запись на события, заявки в клубы/проекты/программы и (с 1.6.85) работы/голоса в конкурсах и заявку работодателя.

## Направления (модули)

Kill-switch: `MODULE_FLAG_KEYS`. Выключенный публичный модуль уходит на `/unavailable` (режим «скоро» или «скрыто»). TECH обходит флаги.

| Модуль | Публично | Создание контента | Участие |
| --- | --- | --- | --- |
| Афиша / events | `/events` | Админ: бронирования | Запись, билеты `/tickets`, join API |
| Клубы / проекты / пространства | каталоги + карточка студии | Админ: `AdminYouthStudioForm`, черновик не в ленте | Заявка (`/api/applications`), для пространств — бронь/коворкинг |
| Куда сходить | `/places` | Админ + галерея файлов | Просмотр |
| Гранты / Добро / Самоуправление | `/grants` `/dobro` `/self-gov` | Админ programs | Заявка на программу |
| Вакансии | `/vacancies` | Админ + заявка стать работодателем | Отклик / кабинет работодателя |
| Конкурсы | `/contests` | Админ | Работа / голос (eligibility) |
| Галерея | `/gallery` | Админ/загрузка | Просмотр |
| Новости, CMS-страницы, FAQ, документы | публичные ленты | Админ pages/news/faq/docs | Чтение |
| Сообщения | `/messages` | Пользователь | ЛС; проверка ссылок РКН + шлюз перехода |
| Друзья, игры, портфолио, рефералы, магазин М-баллов, достижения | кабинет | Пользователь / админ наград | По флагу модуля |
| Сканер | `/scanner` `/scan` | — | SCANNER / TECH / право scanner |
| Регистрация | `/register` | — | Флаг `registration` |

Кабинет (`CABINET_NAV`): профиль, витрина, настройки, друзья, сообщения, билеты, заявки, портфолио, рефералы, инструктажи, игры, магазин, достижения, награды. Пункты прячутся вместе с модулем.

## Согласованность создания и участия

- Карточки клуба/проекта/пространства/страницы собираются одним мастером студии; в ленту попадают только опубликованные, не черновики.
- Заявка принимает **ровно одну** цель: проект, клуб или программа.
- Бронь события и join требуют `requireEndUser` + авторитет/лимиты где задано.
- Конкурсы проверяют eligibility (возраст, роль участника).
- Вакансии и работодатели завязаны на флаг `vacancies` и модерацию заявки работодателя.
- Модули можно выключить независимо; участие через API тоже режется `rejectIfModuleDisabled`.

## Права модератора

Права из `MODERATOR_PERMISSIONS` (проекты, клубы, пространства, места, афиша, заявки, CMS, программы, новости, статистика, сканер, портфолио, модерация чатов, вакансии, конкурсы). Неизвестные `/admin/*` закрыты (ADMIN_ONLY). Пользователи, настройки, РКН, бэкап, система — только суперадмин.

## Что сделано в этой итерации

В чате внешняя ссылка больше не открывается сразу: предупреждение, короткая памятка, проверка адреса (схема, IP, punycode, логин в URL, сокращатели, локальный список РКН). Ссылки портала открываются без шлюза. `javascript:` / `data:` не открываются. РКН — без кнопки «Открыть».

Конкурсы и заявка работодателя теперь так же учитывают `moderationPending`, как запись на события.

## Остаточные риски (не блокер)

- Превью картинки в чате всё ещё запрашивает внешний URL (возможна утечка IP); клик по превью уже идёт через шлюз.
- Ссылки в новостях и CMS не проходят этот шлюз — только сообщения.
- SCANNER может читать часть API афиши/занятости — это нужно для входа, не для записи.
- Гость видит каталоги; скрытые модули зависят от флага, не от роли.

## Рекомендации

1. Держать SCANNER/TECH без участия в заявках (уже так).
2. Не выдавать модератору лишние permissions «на всякий случай».
3. Для новых публичных API участия сразу вызывать `requireEndUser`, а не только проверку роли.
